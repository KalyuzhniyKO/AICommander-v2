## Риски и приоритеты

**P0 — доступ и безопасность.** Нынешние `/tasks` и `/taskflow/*`, включая `owner-decision`, не проверяют личность. `python -m backend.app.main` привязывает сервер к `127.0.0.1`, но альтернативный способ запуска FastAPI с bind на LAN откроет эти endpoints. **Не публиковать API в локальную сеть/интернет, не использовать production и секреты.** `owner_approve` сейчас меняет mock-state в SQLite, **не разрешает реальный Git merge/deploy**. OfflineExecutor исполняет утверждённый argv с правами пользователя; для недоверенного кода требуется настоящая песочница.

**P1 — интеграция.** [PR #30](https://github.com/KalyuzhniyKO/AICommander-v3/pull/30) остаётся Draft и `mergeable=false`. Сохранить уже объединённые taskflow/Executor, согласовать DB migration и API middleware, защитить `/taskflow/*`, добавить отрицательные auth/CSRF и UI-тесты, запустить CI на новом head. Старый зелёный CI PR #30 относится к прежней базе и **недостаточен для merge**. После этого валидировать real Zorin inventory, Hermes → OmniRouter, Codex/QA/PR.

**P2 — документация.** В старых README, IMPLEMENTATION, ROADMAP, GitHub templates обнаружены устаревшие утверждения об отсутствии offline executor и taskflow, о v2 `main` и о необходимости создать отдельный v3. Ссылки на старый адрес GitHub перенаправляются, но требуют актуализации. [Задача #23](https://github.com/KalyuzhniyKO/AICommander-v3/issues/23) (rename) уже выполнена. Модельные рекомендации в roadmap **не доказывают актуальную доступность этих моделей в Codex**.

## Подтверждённое и не подтверждённое

Подтверждены GitHub repository/branches, исходники и конфигурация, шесть успешных CI jobs, состояния PR #30/#35. Не подтверждены живые Hermes/Codex/OmniRouter, текущий model inventory, сетевые политики Zorin, реальное использование панели MacBook и E2E на warehouse_config. В [частичном Zorin-аудите](ZORIN_INTEGRATION.md) отдельно обозначены проверки по исходникам и результаты, **сообщённые владельцем**, а не подтверждённые системным тестом.

## Что возможно без Codex

Подключённый GitHub-инструмент позволяет самостоятельно читать, ревьюить и править файлы, создавать ветки/PR/Issues, проверять CI и объединять безопасные изменения после разрешения владельца. **Это возможности подключения в ChatGPT, а не приложения AICommander.** Изменения в локальных ОС, запуск отдельных тестов и интеграционные работы требуют среды исполнения; из одного зелёного CI нельзя выводить работоспособность на production.
