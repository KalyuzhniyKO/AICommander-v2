# Панель владельца с MacBook

Этап #19 выполнен вне очереди по явному разрешению владельца. Панель работает поверх foundation: текстовые раунды, проекты, роли, артефакты, сохранённые решения и фоновые задачи. Интеграции #14–#18 пока отсутствуют; git diff, реальные тесты задач и стоимость показываются как недоступные. Утверждение текста не означает проверку кода.

## На тестовом Zorin

Используйте отдельный checkout и тестовую SQLite. Production не затрагивается. Python 3.11–3.13:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
cp .env.example .env
cp config/models.example.json config/models.json
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

Запишите полученный пароль в серверный `.env` как `PANEL_PASSWORD`, логин — `PANEL_USER=owner`. `.env` исключён из Git. Пароль панели отличается от ключа провайдера; frontend не содержит их и не хранит в localStorage. Браузер обрабатывает HTTP Basic авторизацию сам. Смена серверного пароля отзывает старые учётные данные.

Запуск: `python -m backend.app.main`. Сервер слушает только `127.0.0.1:8000`. При отсутствующем/коротком пароле все ресурсы возвращают 503, без авторизации — 401. Host ограничен localhost/loopback. Не используйте несколько uvicorn workers или параллельные процессы на одной БД: startup восстанавливает прерванные задачи в состояние failed. Прямое размещение API в LAN/интернете не поддерживается.

## На MacBook

Один раз установите SSH tunnel, заменив адрес и логин:

```bash
ssh -N -L 127.0.0.1:8000:127.0.0.1:8000 zorin-user@zorin-host
```

Можно использовать адрес Zorin в Tailscale/VPN как `zorin-host`. Затем откройте `http://127.0.0.1:8000` в браузере MacBook и введите логин/пароль панели. HTTP Basic применяется только внутри локального подключения и зашифрованного SSH tunnel. Настройка туннеля остаётся отдельным шагом; создание, запуск, остановка и принятие задач после подключения выполняются без терминала.

## Решения владельца

- Создание задачи сохраняет её в выбранном проекте, запуск выполняет раунд в фоне.
- `approve` доступен только после успешных ответов всех вызванных ролей (`awaiting_owner`). Подтверждает текст, не запускает merge/deploy.
- `reject` сохраняет решение и комментарий; повторный запуск доступен.
- `stop` переводит `running → stopping`. Новые роли, retries и fallback не вызываются. Текущий HTTP-запрос не прерывается принудительно и ограничен timeout. Его ответ после остановки не сохраняется как принятый артефакт. По завершении — `stopped`.
- Повторный запуск запрещён во время `running/stopping` и после `approved`; прежние API также проверяют эти состояния.
- При перезапуске сервера прерванная задача становится failed; повтор запускается явно владельцем.

Все изменяющие API требуют `X-AICommander-Request: 1`; чужой Origin отклоняется. CORS не включён. CSP запрещает сторонние скрипты и встраивание в iframe. JSON очищается от настроенного пароля/ключа, Bearer и `sk-…`; это не универсальный классификатор секретов. Не добавляйте другие секреты в задачи и артефакты. В panel/status отсутствуют raw provider errors и серверные конфигурации; неизвестная стоимость не отображается как нулевая.

## Проверка

```bash
python -m pytest -q
python -m pip install -r requirements-ui.txt
python -m playwright install chromium
RUN_UI_TESTS=1 python -m pytest -q tests/ui
```

GitHub Actions выполняет прежнюю Python/Linux/Windows матрицу и отдельный Chromium UI job. UI использует временную БД и mock провайдеров; реальные ключи и запросы моделей отсутствуют. Реальные соединения с Zorin/Hermes/OmniRouter не проверены. Этап #20 не запускался.
